# 第 1 章：准备与原理

> 本章目标：装好工具，理解**mod 加载流水线**（全书最重要的一张图），并做出一个"能亮起来"的最小 mod。

## 1.1 需要的工具

| 工具 | 干什么用 | 必需？ |
|---|---|---|
| **RimWorld 游戏本体** | 测试；编译 C# 时引用它的 DLL | ✅ 必需 |
| **文本编辑器**（VS Code 推荐） | 写 XML / C# | ✅ 必需 |
| **.NET SDK** 或 **Visual Studio 2022** | 把 C# 编译成 DLL | 写 C# 才需要（第 4 章起） |
| dnSpy / RimSage MCP | 反编译查看原版代码 | 可选，进阶用 |

> 本教程用的 `build.bat` 只需要 **.NET SDK**（命令行 `dotnet build`）。如果你更习惯图形界面，Visual Studio 2022 也行（安装时勾选".NET 桌面开发"）。

## 1.2 Mod 放在哪、长什么样

RimWorld 会读取 `<游戏目录>/Mods/` 下的每个子文件夹，每个子文件夹就是一个 mod。
本项目就是一个标准 mod，目录结构如下（先有个印象，后面逐章细讲）：

```
Pooi-s-Mountain-Moving/
├── About/About.xml        # 元信息：名字、作者、支持版本（必需）
├── Defs/                  # XML 数据定义（"是什么"）
├── Patches/               # XML 补丁（修改原版数据）
├── Assemblies/            # 编译出来的 .dll 放这里（C# mod 才有）
├── Textures/              # 贴图
├── Languages/             # 翻译
└── Source/                # C# 源码（游戏不读它，只是留着编译用）
```

> ⚠️ 游戏**只认** `About / Defs / Patches / Assemblies / Textures / Sounds / Languages` 这些约定好的目录名。`Source`、`tools`、`tutorial` 这类是给人看的，游戏会忽略。

## 1.3 全书最重要的一张图：mod 加载流水线

启动游戏勾选 mod 后，RimWorld 大致按下面的顺序加载。**理解它能解释绝大多数"为什么不生效"：**

```
阶段A  读所有 mod 的 About.xml
        → 确定启用哪些 mod、先后顺序、依赖是否满足
            │
阶段B  加载每个 mod 的 Assemblies（.dll）
        → 你的 C# 类（Designator、JobDriver…）此刻"存在"了
            │
阶段C  解析每个 mod 的 Defs（XML）
        → 但先把 Patches/ 里的补丁"打"到 XML 上，再解析成 Def
            │
阶段D  全部 Def 解析完后：交叉引用解析（ResolveReferences）
        → 绑定 DefOf、实例化 designator、把 XML 里的类名变成真正的 C# 对象
            │
阶段E  加载语言文件（Keyed / DefInjected），替换显示文本
            │
        → 进主菜单
```

**由这张图能直接推出三条铁律：**

1. **XML 里写的 C# 类名，必须已经编译进 DLL**（因为 B 在 C/D 之前）。
   所以改了 C# 必须重新编译、并重启游戏才生效。
2. **DefOf 的字段名必须和 XML 的 `defName` 一字不差**（因为在 D 阶段按名字绑定）。
3. **补丁（Patch）是在 XML 解析前打上去的**（C 阶段），所以它能改任何原版/别人 mod 的 Def。

## 1.4 最小可运行 mod：先点亮再说

别急着写功能。先用**最少的文件**确认"游戏认得我的 mod"。

**第 1 步**：在 `<RimWorld>/Mods/` 下新建文件夹，比如 `MyFirstMod`。

**第 2 步**：在里面新建 `About/About.xml`，内容（这就是本项目 `About/About.xml` 的精简版）：

```xml
<?xml version="1.0" encoding="utf-8"?>
<ModMetaData>
  <packageId>yourname.myfirstmod</packageId>   <!-- 全小写、全局唯一，改成你的 -->
  <name>My First Mod</name>
  <author>你的名字</author>
  <supportedVersions>
    <li>1.6</li>
  </supportedVersions>
  <description>我的第一个 mod。</description>
</ModMetaData>
```

逐字段说明：

| 字段 | 含义 | 注意 |
|---|---|---|
| `packageId` | mod 的"身份证号"，**全小写、无空格、全局唯一** | 习惯写法 `你的ID.mod名` |
| `name` | 显示名 | 随便起 |
| `author` | 作者 | 写你自己 |
| `supportedVersions` | 兼容的游戏版本 | 本教程目标 `1.6` |
| `description` | 描述 | 支持换行 |

**第 3 步**：启动游戏 → 选项 → Mod → 勾选 **My First Mod** → 应用。
没有红字、列表里能看到它，就成功了——你已经做出了一个（啥也不干的）合法 mod。

> **这就是开发循环的雏形**：改文件 →（如有 C# 则编译）→ 重启游戏/重载 → 看效果。
> 纯 XML 的改动有时能热重载，但**带 C# 的 mod 改代码后必须重启游戏**，养成重启的习惯最稳妥。

## 1.5 关于"热重载"

- 改 **XML / 贴图 / 翻译**：主菜单 `选项 → Mod` 里取消勾选再勾上，或用开发者模式的重载按钮，通常**不用重启**。
- 改 **C#（.dll）**：**必须完全重启游戏**。DLL 一旦加载进进程就卸不掉。

## 动手练

1. 按 1.4 做出 `MyFirstMod` 并在游戏里点亮它。
2. 故意把 `About.xml` 里的某个标签拼错（比如 `<name>` 写成 `<nam>`），重启看报什么错——**提前习惯看报错**（第 8 章细讲）。

## 本章小结

- 工具：游戏 + 编辑器 +（C# 阶段才需要的）.NET SDK。
- 记住加载流水线五阶段：**About → DLL → Defs(先打补丁) → 解析引用 → 语言**。
- 最小 mod 只需要一个 `About/About.xml`。
