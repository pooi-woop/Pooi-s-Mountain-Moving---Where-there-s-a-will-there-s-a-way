# 第 6 章：持久化与 Mod 设置

> 本章目标：理解"进度为什么要单独存起来"，学会用 MapComponent + Scribe 存数据，并做出一个 Mod 设置面板。
> 打开对照：`MapComponent_RoofRemoval.cs`、`MountainMovingSettings.cs`、`MountainMovingMod.cs`

## 6.1 先想明白一个问题：进度存哪？

凿一格岩顶要约 2 个游戏日。小人**一定会中途去吃饭、睡觉**，你还会**存档、读档**。
问题来了：**凿了一半的进度，存哪里才不会丢？**

逐个排除错误答案：

| 存哪 | 行不行 | 原因 |
|---|---|---|
| 存在 Job（这次工作）里 | ❌ | 小人一被打断（去吃饭），Job 就没了，进度跟着没了 |
| 存在 C# 静态变量里 | ❌ | 静态变量不随存档保存，读档就丢 |
| 存在 Mod 设置里 | ❌ | 设置是全局的、不分地图不分存档，会串档 |
| **存在一个"跟着地图存档走"的组件里** | ✅ | 这才是正解 → **MapComponent** |

> 设计直觉：**凡是"要跟着存档保存"的自定义数据，都需要一个 Component。**
> 按作用域分三种：`MapComponent`（某张地图）、`WorldComponent`（整个大世界）、`GameComponent`（本局游戏）。凿岩进度属于"某张地图"，所以用 `MapComponent`。

## 6.2 MapComponent：按格子存进度

`MapComponent_RoofRemoval` 的核心就是一个字典：`格子索引 → 已凿进度`。
（用 `int` 格子索引做键，比存坐标更容易序列化，是个实用小技巧。）

```csharp
public class MapComponent_RoofRemoval : MapComponent
{
    private Dictionary<int, float> progress = new Dictionary<int, float>();

    public MapComponent_RoofRemoval(Map map) : base(map) { }

    public float GetProgress(IntVec3 cell) { ... }   // 读
    public void  SetProgress(IntVec3 cell, float v) { ... } // 写
    public void  ClearProgress(IntVec3 cell) { ... }  // 清
}
```

### 惰性注入：怎么把组件"放"到地图上（且不用 Harmony）

原版不会自动帮你创建自定义 MapComponent，要自己动手。本项目用一个静态工厂方法，**第一次用到时才创建并加进 `map.components`**：

```csharp
    public static MapComponent_RoofRemoval For(Map map)
    {
        foreach (var c in map.components)
            if (c is MapComponent_RoofRemoval found) return found;  // 已存在就直接用
        var comp = new MapComponent_RoofRemoval(map);
        map.components.Add(comp);                                    // 没有就新建一个加进去
        return comp;
    }
```

之后任何地方需要它，都写 `MapComponent_RoofRemoval.For(map)` —— **有则取之，无则建之**。
这样就不需要一个 Harmony 补丁去"注册"组件了。

### 存进存档：ExposeData + Scribe

要让数据**跟着存档走**，重写 `ExposeData()`，用 `Scribe_*` 系列方法声明"这个字段要存"：

```csharp
    public override void ExposeData()
    {
        base.ExposeData();
        Scribe_Collections.Look(ref progress, "PMM_roofRemovalProgress", LookMode.Value, LookMode.Value);
        if (progress == null) progress = new Dictionary<int, float>();  // 读旧档兜底
    }
```

- `Scribe_Collections.Look(ref 集合, "键名", ...)`：存档时把 `progress` 写进存档文件，读档时读回来。
- `"PMM_roofRemovalProgress"` 是存档里的键名，**别拼错**。
- 游戏保存地图时会把 `map.components` 里每个组件的 `ExposeData` 都调一遍，于是我们的进度就进了存档。

**Scribe 速查（常用的就这几个）：**

| 方法 | 存什么 |
|---|---|
| `Scribe_Values.Look(ref x, "key", 默认值)` | int / float / bool / string |
| `Scribe_Collections.Look(ref list, "key", LookMode.Value)` | 列表 / 字典 |
| `Scribe_References.Look(ref thing, "key")` | 对某个 Thing/Pawn 的引用 |
| `Scribe_Defs.Look(ref def, "key")` | 对某个 Def 的引用 |

### 顺带：定期大扫除

组件里还有一个 `MapComponentTick()`，每 500 tick 清理一次"失效进度"和"残留标记"（比如玩家取消指派、或岩顶被别的手段弄没了）。这是个好习惯：**别让无用数据越攒越多**。新手阶段可以先不细究，知道它在做"保洁"即可。

## 6.3 ModSettings：做一个设置面板

让玩家自己调"每格要凿多久"。设置和存档无关，全局生效。
看 `MountainMovingSettings.cs`：

```csharp
public class MountainMovingSettings : ModSettings
{
    public const float DefaultWorkAmount = 120000f;   // 默认 120000 tick ≈ 2 个游戏日
    public float workAmount = DefaultWorkAmount;
    public bool  notifyOnComplete = false;

    public void DoWindowContents(Rect inRect)          // 画设置界面
    {
        Listing_Standard l = new Listing_Standard();
        l.Begin(inRect);
        l.Label("PMM_Setting_WorkAmount".Translate(...));   // 一行说明文字
        workAmount = l.Slider(workAmount, 6000f, 600000f);  // 一个滑块（0.1~10 天）
        l.CheckboxLabeled("PMM_Setting_Notify".Translate(), ref notifyOnComplete); // 一个勾选项
        l.End();
    }

    public override void ExposeData()                   // 设置也要存（存到全局配置，不是存档）
    {
        base.ExposeData();
        Scribe_Values.Look(ref workAmount, "workAmount", DefaultWorkAmount);
        Scribe_Values.Look(ref notifyOnComplete, "notifyOnComplete", false);
    }
}
```

- `Listing_Standard` 是画设置界面的好帮手：`Label`（文字）、`Slider`（滑块）、`CheckboxLabeled`（勾选框）一行一个。
- 设置的 `ExposeData` 会被存到 RimWorld 的**全局 mod 配置**里（不是某个存档），所以换存档设置还在。

而 `MountainMovingMod`（第 4 章的入口类）负责把这个设置接进来：

```csharp
settings = GetSettings<MountainMovingSettings>();          // 入口里加载
public static float WorkAmount => settings != null ? settings.workAmount : ...; // 给别处用的安全取值
```

于是第 5 章的 `TickWork` 里 `MountainMovingMod.WorkAmount` 就能读到玩家设置的"每格工作量"。

## 本章小结

- 要随存档保存的数据 → 用对应作用域的 Component（这里是 MapComponent）。
- 惰性注入 `For(map)` 让我们不依赖 Harmony 也能用上 MapComponent。
- `ExposeData` + `Scribe_*` 声明"哪些字段要存"。
- `ModSettings` + `Listing_Standard` 做出全局设置面板。
