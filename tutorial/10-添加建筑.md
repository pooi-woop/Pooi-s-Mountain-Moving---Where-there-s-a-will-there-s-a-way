# 第 10 章：添加建筑（Building ThingDef）

> 本章目标：用**纯 XML**（不写一行 C#）给游戏加一座能被小人建造的建筑，并搞懂它怎么出现在"建筑师"菜单里。
> 打开对照：本章我们一起新建 `Defs/ThingDefs/PMM_Buildings.xml`（基础篇的 mod 里还没有这个文件）

## 10.1 为什么：建筑其实也是 ThingDef

回忆第 2 章那句话——**游戏里一切"内容"都是 Def**。第 9 章做的"物品"是 Def，本章的"建筑"也是 Def，而且它们俩**是同一种 Def：`ThingDef`**。区别只在一个字段：

```xml
<ThingDef>
  <category>Item</category>       <!-- 这是"物品"（第 9 章） -->
</ThingDef>

<ThingDef>
  <category>Building</category>   <!-- 这是"建筑"（本章） -->
</ThingDef>
```

`<category>` 告诉游戏"这是个什么东西"：`Item`（能捡起来搬走的物品）、`Building`（造在地图上不动的建筑）、`Pawn`（小人/动物）……

**好消息：做建筑基本不用写 C#。** 因为"一座建筑占几格、要多少料、长什么样"全是**数据**——正是 XML 的主场。这会是你"纯 XML 就能做出来的第一个大件"。

### 站在 BuildingBase 的肩膀上

和武器继承 `BaseWeapon` 一样，建筑有个现成的父类 `BuildingBase`。继承它，你就免费得到一长串建筑默认行为（"不可搬走""可被拆除""有耐久"……），**还包括上面那行 `<category>Building</category>`——所以我们自己不用再写它**。

原版的建筑继承链是：

```
BaseBuilding → BuildingBase → 你的建筑
```

```xml
<ThingDef ParentName="BuildingBase">
  ...只写和父类不一样的部分...
</ThingDef>
```

> 这正是第 2 章讲的 `ParentName` 继承。

## 10.2 一个完整示例：切石台

凿了那么多山，运出来的石块堆成山——我们加一台"**切石台**"，把石块加工成有用材料。（"怎么加工"属于配方，留给第 11 章；本章先把这台**能造出来的建筑**做出来。）

新建 `Defs/ThingDefs/PMM_Buildings.xml`：

```xml
<?xml version="1.0" encoding="utf-8"?>
<Defs>
  <ThingDef ParentName="BuildingBase">
    <defName>PMM_StonecuttingBench</defName>
    <label>stonecutting bench</label>
    <description>A sturdy bench for cutting stone blocks hauled out of the mountain.</description>

    <!-- 占地大小：（宽, 高），单位是"格" -->
    <size>(3,1)</size>

    <!-- 出现在「建筑师」菜单的哪个分页 -->
    <designationCategory>Production</designationCategory>

    <!-- 建造要多少固定材料 -->
    <costList>
      <Steel>50</Steel>
      <ComponentIndustrial>3</ComponentIndustrial>
    </costList>

    <statBases>
      <WorkToBuild>2500</WorkToBuild>     <!-- 建造工作量（tick） -->
      <MaxHitPoints>200</MaxHitPoints>    <!-- 耐久 -->
      <Flammability>0.5</Flammability>    <!-- 可燃性 0~1 -->
    </statBases>

    <passability>Impassable</passability>            <!-- 小人/物品能不能穿过 -->
    <fillPercent>0.7</fillPercent>                   <!-- 贴图在格子里填多满（0~1） -->
    <terrainAffordanceNeeded>Medium</terrainAffordanceNeeded>  <!-- 对地面/地板的要求 -->
    <rotatable>true</rotatable>                       <!-- 能不能转向摆放 -->

    <graphicData>
      <texPath>Things/Building/PMM_StonecuttingBench</texPath>  <!-- 贴图（规则见第 7 章） -->
      <graphicClass>Graphic_Single</graphicClass>
      <shaderType>CutoutComplex</shaderType>
      <drawSize>(3,1)</drawSize>                      <!-- 贴图画多大，一般和 size 一致 -->
    </graphicData>
  </ThingDef>
</Defs>
```

就这些——不需要任何 C#。勾选 mod 重载后，就能在「建筑师 → 生产」里找到它、让小人把它造出来。

## 10.3 关键字段逐个讲

| 字段 | 干什么 | 注意 |
|---|---|---|
| `size` | 建筑占几格，格式 `(宽,高)` | **格式是铁律**：必须是 `(3,1)`，写成 `3,1`、`(3, 1)`（多空格）或 `3x1` 都会出问题 |
| `designationCategory` | 决定它出现在"建筑师"的哪个分页 | 见 10.4 |
| `costList` | 建造要多少**固定材料** | 里面填**材料的 defName**（如 `Steel`、`ComponentIndustrial`），填错就报红 |
| `WorkToBuild` | 建造工作量，单位 **tick**（1 秒≈60 tick，见第 5 章） | 越大造越久；实际快慢还受小人建造速度影响 |
| `MaxHitPoints` | 耐久度 | 挨打、年久失修都会掉 |
| `Flammability` | 可燃性，`0`~`1` | `0` 不燃，`1` 一点就着 |
| `passability` | 能否被穿过 | `Impassable`（完全挡路）/ `PassThroughOnly` / `Standable` |
| `fillPercent` | 贴图在格子里填多满，`0`~`1` | 低于 1 表示没填满，也影响"能不能隔着它开枪" |
| `terrainAffordanceNeeded` | 对地面/地板的最低要求 | `Light` / `Medium` / `Heavy` |
| `rotatable` | 能不能转向 | `true` / `false` |
| `graphicData` | 贴图相关 | `texPath` 规则同第 7 章：去掉 `Textures/` 前缀和 `.png` |

> 顺带区分：武器/装备常用 `stuff` 材料系统（玩家自选材料），而**建筑用 `costList`**（材料写死）。别记混。

## 10.4 它怎么出现在"建筑师"菜单

第 3 章我们想往"命令"面板加个按钮，得写补丁；但**建筑不用**——只要填了 `designationCategory`，游戏会自动把它放进对应分页。

`designationCategory` 填的是一个**分类的 defName**。常见取值和它对应的分页：

| 填这个值 | 出现在「建筑师」的 | 典型建筑 |
|---|---|---|
| `Production` | 生产 | 工作台、炉子 |
| `Furniture` | 家具 | 床、桌、椅 |
| `Structure` | 结构 | 墙、门、柱 |
| `Power` | 电力 | 发电机、电池 |
| `Temperature` | 温度 | 加热器、制冷机 |
| `Security` | 防卫 | 炮塔、陷阱 |
| `Recreation` | 娱乐 | 台球桌、棋盘 |
| `Misc` | 杂项 | 不好归类的 |

（分页的中文名以游戏内实际翻译为准；XML 里**只能填左边那列英文 defName**。）

> 拿不准某个建筑该进哪个分页？**先查原版**：去 `<RimWorld>/Data/Core/Defs/` 搜一个同类建筑，把它的 `designationCategory` 抄过来。也可用 RimSage：`get_def_details("FueledSmithy")`。

## 10.5 更复杂的行为：先点到为止

现在的切石台还只是个"能造出来的空壳"，不会干活。想让它真正有用，会用到这些进阶手段：

| 想要的效果 | 靠什么 | 哪章讲 |
|---|---|---|
| 耗电 / 通电 | `comps` 里的 `CompProperties_Power` | 第 13 章 |
| 变成"工作站台"、能做东西 | `CompProperties_WorkTable` + **配方 RecipeDef** | 第 11 章 |
| 研究解锁后才可建 | `researchPrerequisites` | 第 11 章 |
| 更花哨的自定义逻辑 | 自己写 `ThingComp`（C#） | 第 13 章 |

本章你只要记住：**这些都是在 ThingDef 上继续"加挂"东西**；楼的骨架（占地、材料、贴图、菜单）你已经会搭了。

## 10.6 常见坑

- **size 格式写错**：`(3,1)` 才对；`(3, 1)`、`3,1`、`3x1` 都会让占地错乱或直接报错。
- **costList 填错材料 defName**：木头是 `WoodLog` 不是 `Wood`，零部件是 `ComponentIndustrial` 不是 `Component`。**填之前先查原版**确认 defName，填错就红字。
- **designationCategory 拼错**：大小写敏感，`production`、`Product` 都不行；填错了建筑就在菜单里"消失"。
- **贴图不显示 / 显示成粉色块**：`texPath` 指错了。对照第 7 章检查路径；测试期可先借一个原版建筑的贴图路径。
- **旋转后贴图不转向**：`Graphic_Single` 只有一张图，转向时不会跟着变。要让建筑转向也好看，得用多角度贴图（进阶，先查原版）。

## 动手练

1. 把 `designationCategory` 从 `Production` 改成 `Misc`，重载后去「建筑师」找找切石台跑到哪个分页了——亲身体会这个字段的作用（再改回来）。
2. 故意把 `<size>(3,1)</size>` 写成 `<size>(3, 1)</size>`（中间多个空格），重载看报什么错，体会"格式是铁律"；改回来之后，把 `Steel` 的数量从 `50` 改成 `5`，看建造所需材料是不是变少了。

## 本章小结

- 建筑是一种 `ThingDef`，`ParentName="BuildingBase"` 继承默认值（连 `category` 都帮你写好了）。
- 核心字段：`size`、`designationCategory`、`costList`、`WorkToBuild`、`passability`、`fillPercent`、`terrainAffordanceNeeded`、`graphicData`。
- `designationCategory` 决定它进"建筑师"的哪个分页，**不用写补丁**。
- 耗电 / 配方 / 自定义逻辑 → 留给第 11、13 章。
