# 第 8 章：测试、调试与发布

> 本章目标：会开开发者模式、看得懂红字日志、按清单测试本 mod，并知道怎么把它打磨到能发布。

## 8.1 开发者模式（Dev Mode）—— 你的好朋友

`选项 → 常规 → 开发者模式` 打开。进存档后屏幕上方会多一排图标，常用的：

| 功能 | 用途 |
|---|---|
| **Open debug log**（也可直接看 Player.log） | 看报错/日志 |
| **God Mode** | 建造立刻完成、随便铺东西——用来快速搭测试场景 |
| Spawn Thing / Spawn Pawn | 凭空生成物品/小人 |
| **Destroy / T: Kill** | 删掉测试产生的杂物 |

**测试本 mod 的快速场景**：开 God Mode，在山地地图上框选一片厚岩顶 → 派建造工去凿；把设置里"每格工作量"调到最小（约 0.1 天），几秒就能凿掉一格，确认链路通了再调回正常值。

## 8.2 看日志：Player.log 在哪

报错（红字）都写在日志里。路径：

```
C:\Users\<你>\AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios\Player.log
```

> `AppData` 默认隐藏，可在资源管理器地址栏直接粘贴上面的路径。
> 也可以在游戏里点 Dev Mode 的日志按钮直接看。

**读日志的顺序**：从下往上找**第一条** `Error`/`Exception`（后面的错常常是第一条引发的连锁反应）。

## 8.3 常见红字对照表

| 日志里的关键信息 | 大概率原因 | 怎么修 |
|---|---|---|
| `Could not find type ... Designator_RemoveThickRoof` | DLL 没编译 / 没放进 `Assemblies/` | 重跑 `build.bat`，确认 DLL 存在 |
| `Could not resolve cross-reference ... PMM_RemoveThickRoof` | DefOf 字段名和 defName 不一致 | 逐字核对两边拼写 |
| `Patch operation failed` | xpath 没定位到节点 | 检查 xpath、确认目标字段名是查原版得来的 |
| `Could not find texture ... PMM/UI/...` | 贴图路径写错 / 文件不存在 | 对照第 7 章路径规则 |
| 翻译键原样显示（如 `PMM_Setting_Notify`） | 缺英文兜底翻译 | 补 `Languages/English/Keyed/` 里对应的键 |
| 启动直接白窗/卡死 | 多为 XML 标签拼错、嵌套错误 | 检查最近改过的 XML 是否标签闭合 |

## 8.4 本 mod 的验收清单

照这个过一遍，全绿才算"测试通过"：

- [ ] Mod 列表能勾选，无红字
- [ ] 「建筑师 → 命令」里有"移除厚岩顶"按钮，图标正常
- [ ] 在厚岩顶上框选，格子出现琥珀色 X 标记
- [ ] 勾选"建造"的小人会走过来，头顶有进度条
- [ ] **中途让小人去吃饭/睡觉，回来进度接着走（不清零）** ← 本 mod 的关键
- [ ] 存档 → 读档 → 进度还在
- [ ] 凿满后岩顶消失、露出天空（变亮）
- [ ] 普通屋顶/薄顶**不会**被这个指令选中（只认厚岩顶）
- [ ] 山体深处走不到的格子不会派活（属正常）

## 8.5 从"能用"到"能发布"：正规化

测试通过后，做这些收尾（对应 `workflows/formalize-mod.md`）：

1. **清理命名**：`packageId`、`author` 改成你的正式发布 ID（测试期随便，发布要讲究）。
2. **补 `About/Preview.png`**：640×360 的预览图，Workshop 和 Mod 列表会用。
3. **替换正式贴图**：把程序化生成的图标换成更精致的原创图。
4. **完善 `description`**：写清功能、用法、兼容性、卸载注意事项。
5. **考虑兼容性**：是否需要 `LoadFolders.xml` 支持多版本？是否和常见 mod 冲突？

## 8.6 发布到 Steam Workshop

准备好后，游戏内 `选项 → Mod → 选中你的 mod → 上传到 Workshop` 即可（需要 Steam 在线）。
发布后记得把 Workshop 页面的介绍、截图补全。

## 8.7 进阶路线（接下来学什么）

本教程刻意**没用 Harmony**，因为我们是"新增"内容。等你想做下面这些事时，就该学 Harmony 了：

| 想做 | 需要 |
|---|---|
| 改原版某个方法的行为（比如让原版"移除屋顶"也能选厚岩顶） | Harmony Prefix/Postfix |
| 给原版的某类物品统一加新行为 | Harmony + ThingComp |
| 更复杂的 AI / 界面 | 更深的 C#（ThinkTree、Window） |

推荐资源：
- 原版 Def：`<RimWorld>/Data/Core/Defs/`（最好的老师，**先查后写**）
- 反编译看原版 C#：dnSpy 打开 `Assembly-CSharp.dll`
- RimSage MCP：自然语言搜源码
- Harmony 官方 Wiki

## 本章小结

- Dev Mode + Player.log 是调试两大件；从下往上找第一条错。
- 按 8.4 清单验收本 mod。
- 正规化五步走，再走 Workshop 发布；想改原版行为时去学 Harmony。
