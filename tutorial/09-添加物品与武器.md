# 第 9 章：添加物品与武器（ThingDef）

> 本章目标：不写一行 C#，纯用 XML 给游戏加一把能制作、能装备、能砍人的近战武器，并看懂每个字段。
> 打开对照：本章是独立新示例，对照 skill 模板 `weapon-melee.xml` / `weapon-ranged.xml`，以及原版 `RimWorld/Data/Core/Defs/ThingDefs_Misc/Weapons/BaseWeapons.xml`。

> **进阶篇说明**：基础篇（01–08 章）围绕示例 mod「Pooi's Mountain Moving」讲了它用到的知识；进阶篇讲它**没用到、但做 mod 几乎必遇到**的主题。本章新示例仍沿用 `PMM_` 前缀。

## 9.1 为什么说"加把武器"是最适合新手的第一个内容 mod？

- **纯 XML，零 C#**：武器的全部——伤害、重量、贴图、在哪造——都是"数据"，一个 XML 文件搞定。
- **有现成骨架**：原版把武器的通用配置抽成了"父类"，你继承后只写差异，照抄结构就行。
- **反馈极快**：改完进游戏，立刻能看到它躺在库存里、能装备、能砍人。这种即时成就感是坚持下去的燃料。

回忆第 1 章的心智模型：**XML 定义"数据是什么"**。一把刀的伤害值是 15 还是 50，是数据；这一章我们全在跟数据打交道。

## 9.2 ThingDef 是什么？

**Thing = 游戏里看得见摸得着的东西**：物品、武器、建筑、植物、小人。`ThingDef` 就是描述这类东西的 XML 数据表，也是所有 Def 里最常用的一种。

武器 = 一个 ThingDef，再加上"能被装备、有攻击方式（tools）、有贴图、能被制作（recipeMaker）"这些字段。

## 9.3 ParentName 继承：别重复造轮子

第 2 章提过 `ParentName` 继承，现在它真正派上用场了。原版把武器的几十行通用配置抽成了层层父类：

```
BaseWeapon（thingClass、category，自带 CompEquippable / CompForbiddable / CompStyleable）
└── BaseMeleeWeapon（thingCategories = WeaponsMelee、recipeMaker 骨架、tradeTags……）
    └── BaseMeleeWeapon_Sharp
        └── BaseMeleeWeapon_Sharp_Quality（再加 CompQuality 品质 + CompArt 艺术）
            └── 👈 你的锋利近战武器，ParentName 填它
```

远程武器则是另一条链：

```
BaseGun（thingCategories = WeaponsRanged）
└── BaseGunWithQuality → BaseMakeableGun → BaseHumanMakeableGun（recipeMaker + weaponTags + CompBiocodable）
                                             └── 👈 你的可制作枪械，ParentName 填它
```

**继承帮你省掉的重复劳动**：分类（thingCategories）、可装备/可禁用/品质/艺术等 comps、配方骨架、交易标签……全都不用写。你只写"和父类不同"的部分——名字、数值、贴图、材料。子元素会**合并**进父类定义，比如在 `recipeMaker` 里只写你要覆盖的几行。

## 9.4 完整示例：PMM 开山刀（近战武器，可直接用）

新建文件 `Defs/ThingDefs/PMM_Weapons.xml`，内容如下（严格按 skill 模板的已验证结构）：

```xml
<?xml version="1.0" encoding="utf-8"?>
<Defs>
  <!-- 开山刀：锋利近战武器。父类已备好"可装备/有品质/可制作"骨架，我们只填差异。 -->
  <ThingDef ParentName="BaseMeleeWeapon_Sharp_Quality">
    <defName>PMM_Weapon_MountainCleaver</defName>   <!-- 全局唯一 ID，必须带前缀 -->
    <label>mountain cleaver</label>                  <!-- 显示名（中文翻译走 Languages，见第 7 章） -->
    <description>A heavy blade forged for those who move mountains.</description>

    <possessionCount>1</possessionCount>
    <techLevel>Industrial</techLevel>   <!-- Neolithic / Medieval / Industrial / Spacer / Ultratech -->

    <!-- 材料：用 stuff 系统——50 单位"任意金属材料"，玩家制作时自选钢/玻璃钢/铀…… -->
    <costStuffCount>50</costStuffCount>
    <stuffCategories>
      <li>Metallic</li>
      <!-- <li>Woody</li> -->           <!-- 想让它也能用木头做，取消注释 -->
    </stuffCategories>

    <statBases>
      <MarketValue>300</MarketValue>     <!-- 基础市场价值（银） -->
      <Mass>2.0</Mass>                   <!-- 重量（kg） -->
      <MaxHitPoints>150</MaxHitPoints>   <!-- 耐久度 -->
      <WorkToMake>8000</WorkToMake>      <!-- 制作工作量（tick） -->
    </statBases>

    <equippedAngleOffset>-55</equippedAngleOffset>   <!-- 持握时的贴图角度 -->

    <weaponTags>
      <li>PMM_Mountain</li>              <!-- 武器标签：文化/角色偏好用它认武器 -->
    </weaponTags>

    <!-- 攻击方式：一次挥砍 -->
    <tools>
      <li>
        <label>edge</label>
        <capacities>
          <li>Cut</li>                   <!-- 伤害类型：Cut / Blunt / Stab / Poke -->
        </capacities>
        <power>15</power>                <!-- 基础伤害 -->
        <cooldownTime>1.6</cooldownTime> <!-- 攻击冷却（秒） -->
        <armorPenetration>0.15</armorPenetration>  <!-- 护甲穿透（0~1） -->
      </li>
    </tools>

    <graphicData>
      <texPath>Things/Item/PMM_MountainCleaver</texPath>  <!-- Textures/ 下的路径，不带前缀、不带扩展名 -->
      <graphicClass>Graphic_Single</graphicClass>         <!-- 单张贴图 -->
      <shaderType>CutoutComplex</shaderType>              <!-- 支持材料染色的着色器 -->
    </graphicData>

    <!-- 可制作：研究完锻造（Smithing）、制作技能 3 级可造 -->
    <recipeMaker>
      <researchPrerequisite>Smithing</researchPrerequisite>
      <skillRequirements>
        <Crafting>3</Crafting>
      </skillRequirements>
      <workAmount>8000</workAmount>
    </recipeMaker>
  </ThingDef>
</Defs>
```

## 9.5 关键字段逐个看

| 字段 | 含义 | 备注 |
|---|---|---|
| `defName` | 全局唯一内部 ID | 必须带 `PMM_` 前缀，防撞名 |
| `label` / `description` | 显示名 / 描述 | 中文翻译放 `Languages/`（第 7 章） |
| `techLevel` | 科技等级 | 合法值：`Neolithic`/`Medieval`/`Industrial`/`Spacer`/`Ultratech` |
| `possessionCount` | 可持有个数 | 武器固定写 1 |
| `costStuffCount` + `stuffCategories` | 材料系统 | 见 9.6 |
| `statBases.MarketValue` | 基础市场价值 | 实际售价还受材料、品质影响 |
| `statBases.Mass` | 重量（kg） | |
| `statBases.MaxHitPoints` | 耐久度 | 会被材料进一步修正 |
| `statBases.WorkToMake` | 制作工作量（tick） | |
| `tools` | 攻击方式列表 | 可写多个 `<li>`，如"刃砍 + 柄击" |
| `tools.capacities` | 伤害类型 | `Cut`/`Blunt`/`Stab`/`Poke` |
| `tools.power` / `cooldownTime` | 伤害 / 冷却秒数 | 平衡性的核心旋钮 |
| `graphicData.texPath` | 贴图路径 | `Textures/` 下，**不带前缀、不带扩展名** |
| `recipeMaker` | 让它能被制作 | 研究前置、技能要求、工作量 |

> `thingCategories`（属于"近战武器"分类）父类已经给了，不用写——这就是继承的好处。

## 9.6 costStuffCount 与 costList 的区别（别混用）

- **武器/装备用 stuff 系统**：`costStuffCount` 定"数量"，`stuffCategories` 定"允许哪类材料"。玩家制作时**自选具体材料**（钢、玻璃钢、铀……），成品属性随材料变化——这就是为什么同一把刀，钢的和铀的强度不同。
- **建筑等固定材料用 costList**，直接点名要什么、要多少：

```xml
<costList>
  <Steel>100</Steel>
  <ComponentIndustrial>3</ComponentIndustrial>
</costList>
```

一句话：**想让玩家挑材料 → stuff；想固定死材料 → costList。武器几乎总是前者。**

## 9.7 贴图：测试期先借，发布前换原创

- 路径规则（同第 7 章）：`texPath` 相对 `Textures/`，不含 `Textures/` 前缀、不含 `.png` 后缀；单张图配 `Graphic_Single`。
- **测试期偷懒完全合法**：把 `texPath` 直接指向原版贴图。打开 `RimWorld/Data/Core/Textures/Things/Item/` 逛一圈，看中哪张（比如原版刀具贴图在 `Things/Item/Equipment/` 一带），把它的相对路径填进 `texPath` 即可——你的 mod 里**不需要放任何图片文件**，游戏会直接从 Core 里读。
- **版权红线**：测试归测试，**发布前不要把原版的 .png 文件复制进自己的 mod**——那是 Ludeon 的美术资产。引用路径 ≠ 复制文件。正规化（第 8 章）时换成自己画的或有授权的图。

## 9.8 远程武器：只讲差异

枪械的结构和近战几乎一样，区别就几处（完整骨架见 skill 模板 `weapon-ranged.xml`）：

| 差异点 | 远程武器 |
|---|---|
| ParentName | `BaseHumanMakeableGun`（不可制作的用 `BaseGun` / `BaseGunWithQuality`） |
| 攻击方式 | 不写 `tools`，改写 `<verbClass>Verb_Shoot</verbClass>` |
| 射击参数 | `rangedWeapon_Cooldown`（射击间隔）、`rangedWeapon_WarmupTime`（瞄准时间）、`rangedWeapon_Range`（射程格数） |
| 精度 | statBases 里加 `AccuracyTouch`/`AccuracyShort`/`AccuracyMedium`/`AccuracyLong` |
| 研究前置 | 通常是 `Gunsmithing` 而非 `Smithing` |

## 9.9 常见坑 + 铁律

- **坑 1：`techLevel` 凭记忆写错。** 它是 `Ultratech` 还是 `Ultra`？别猜——以本教程使用的 1.6 已验证模板/reference 为准，答案是 `Ultratech`。更深层的话：**任何字段的取值都不要凭记忆写**，动手前先去原版 `Data/Core/Defs/` 里 `grep` 一个类似 Def 确认（第 2 章的铁律），以你本机的原版文件为最终答案。
- **坑 2：texPath 带了 `Textures/` 前缀或 `.png` 后缀** → 游戏里变成紫黑"丢失贴图"。
- **坑 3：把武器当建筑写 costList**（或反过来），材料需求直接不生效。
- **坑 4：defName 撞名** → 加载红字。永远带前缀。
- **坑 5：改完启动红字** → 开 Dev 模式读 `Player.log`，方法见第 8 章。

## 速查表：做什么武器，继承谁

| 你要做 | ParentName |
|---|---|
| 锋利近战（刀、剑） | `BaseMeleeWeapon_Sharp_Quality` |
| 钝器近战（棍、锤） | `BaseMeleeWeapon_Blunt` |
| 可制作的枪械 | `BaseHumanMakeableGun` |
| 不可制作、只掉落/售卖的枪 | `BaseGun` / `BaseGunWithQuality` |

## 动手练

1. 把 `power` 改成 `40`、`cooldownTime` 改成 `0.5`，进游戏用开发者模式刷一把（第 8 章的 spawn 方法），找只松鼠试试手感——亲身体会"数值即平衡"，然后改回合理值。
2. 在 `stuffCategories` 里加一行 `<li>Woody</li>`，重载后打开制作账单，看能不能选木头；分别做一把木刀和一把钢刀，对比信息面板里伤害与耐久的差异，理解"材料改变成品"。

## 本章小结

- 物品/武器是纯 XML 的 `ThingDef`，结构成熟、反馈快，是新手的最佳练手对象。
- `ParentName` 继承原版父类，省掉分类、comps、配方骨架等重复劳动；近战用 `BaseMeleeWeapon_Sharp_Quality`，远程用 `BaseHumanMakeableGun`。
- 材料用 stuff 系统（`costStuffCount` + `stuffCategories`），区别于建筑的 `costList`。
- 贴图测试期可借原版 `texPath`，但绝不把原版图片复制进 mod 发布。
- 写字段先查原版，别凭记忆——`techLevel` 的取值就是经典翻车点。
