# 第 11 章：配方与研究（RecipeDef + ResearchProjectDef）

> 本章目标：学会两件套——① 用 **RecipeDef** 让玩家在工作台上"制作/加工"东西；② 用 **ResearchProjectDef** 在科技树上加一个研究节点，并用它把配方锁住。做完你会把"**研究 → 解锁配方 → 工作台制作 → 产出物品**"这一整条链打通。
> 打开对照：本章要新建的两个文件 `Defs/RecipeDefs/PMM_Recipes.xml`、`Defs/ResearchProjectDefs/PMM_Research.xml`；动手前先去 `<RimWorld>/Data/Core/Defs/` 里搜 `RecipeDef` 和 `ResearchProjectDef` 抄结构。

## 11.0 先讲为什么：一个物品是"哪来的"？

第 9 章我们做了一件**物品**，第 10 章我们搭了一张**工作台**。但玩家不能凭空变出物品——它得有个"来历"。原版里绝大多数物品的来历都是这条链：

```
ResearchProjectDef（科技树上一个节点）
   │  玩家花研究点把它做完
   ▼  研究完成，解锁……
RecipeDef（一张配方：用什么材料、花多少工、产出什么）
   │  因为配方里写了 researchPrerequisite = 这个研究
   ▼  配方出现在……
工作台（ThingDef，配方的 recipeUsers 里点了它的名）
   │  小人跑过去消耗材料、干满工作量
   ▼  产出……
物品（ThingDef，就是第 9 章做的那个）
```

可以看到，**研究、配方、工作台、物品是四个独立的 Def，靠 defName 互相引用才串成一条线**。本章就是把中间两环（研究 + 配方）补上。这也是内容型 mod 最常用的一招：纯 XML，不需要写 C#。

> 小提醒：原版里"研究"这个 Def 的 XML 标签是 `<ResearchProjectDef>`（很多人口头上叫它 ResearchDef），defName 才用 `<Research...>` 前缀。别写成 `<ResearchDef>`，那个标签不存在。

## 11.1 RecipeDef：一张"配方"

沿用本 mod 的"移山"主题，我们做一张**把碎石块压炼成钢**的配方（挖山挖出一堆石块，正好废物利用）。新建 `Defs/RecipeDefs/PMM_Recipes.xml`：

```xml
<?xml version="1.0" encoding="utf-8"?>
<Defs>
  <RecipeDef>
    <defName>PMM_Recipe_CrushChunkToSteel</defName>
    <label>crush stone chunks into steel</label>
    <description>Break down leftover stone chunks and recover the steel trapped inside.</description>

    <!-- 这张配方能在哪些工作台做（写工作台 ThingDef 的 defName） -->
    <recipeUsers>
      <li>TableMachining</li>
    </recipeUsers>

    <!-- 前置研究（单数）：做完 PMM_RockCrushing 才解锁这张配方 -->
    <researchPrerequisite>PMM_RockCrushing</researchPrerequisite>

    <!-- 技能：干这活算/练"手工"，且手工至少 4 级才能做 -->
    <workSkill>Crafting</workSkill>
    <skillRequirements>
      <Crafting>4</Crafting>
    </skillRequirements>

    <!-- 工作量与速度：2400 tick = 40 秒（1 秒 = 60 tick） -->
    <workAmount>2400</workAmount>
    <workSpeedStat>CraftingSpeed</workSpeedStat>          <!-- 哪个属性让它做得更快 -->
    <efficiencyStat>CraftingEfficiency</efficiencyStat>   <!-- 效率属性（影响耗时/产出） -->
    <effectWorking>Smith</effectWorking>                  <!-- 干活时播的特效，可选 -->

    <!-- 材料：任意 3 个石块（filter 里列几种，就接受哪几种） -->
    <ingredients>
      <li>
        <filter>
          <thingDefs>
            <li>ChunkSandstone</li>
            <li>ChunkGranite</li>
            <li>ChunkLimestone</li>
            <li>ChunkSlate</li>
            <li>ChunkMarble</li>
          </thingDefs>
        </filter>
        <count>3</count>
      </li>
    </ingredients>

    <!-- 固定产出：10 个钢 -->
    <products>
      <li>
        <thingDef>Steel</thingDef>
        <count>10</count>
      </li>
    </products>
  </RecipeDef>
</Defs>
```

**字段速查：**

| 字段 | 含义 |
|---|---|
| `recipeUsers` | 这张配方能在**哪些工作台**做。写工作台 ThingDef 的 `defName`（如 `TableMachining`、`FueledStove`），**不是 label** |
| `researchPrerequisite` | 前置研究（**单数**）。做完该研究，配方才解锁；没做完时配方隐藏 |
| `workSkill` | 干这活**算/练哪个技能**（如 `Crafting`） |
| `skillRequirements` | **最低技能门槛**：`<技能>等级</技能>`，不够的小人接不了这单 |
| `workAmount` | 工作量，单位 tick（1 秒 = 60 tick；`2400` ≈ 40 秒） |
| `workSpeedStat` / `efficiencyStat` | 哪个**属性**加速它 / 影响效率（如 `CraftingSpeed` / `CraftingEfficiency`） |
| `effectWorking` | 干活时播放的特效（EffecterDef，如 `Smith`、`Cook`）。可选 |
| `ingredients` | 材料清单：每项一个 `filter`（接受什么）+ `count`（要几个） |
| `products` | **固定产出**：`thingDef` + `count` |
| `fixedIngredientFilter` | 材料的"**硬范围**"：玩家只能在这些东西里选，改不了（可选） |
| `defaultIngredientFilter` | 材料的"**默认勾选**"：玩家可在账单里自行改选（可选） |

**关于材料的三个 filter，别混：**
- `ingredients` 里的 `filter`：这项材料**具体接受哪些 defName**（或一整类）。
- `fixedIngredientFilter`：给整张配方划死"只能用什么"，玩家无权改。
- `defaultIngredientFilter`：只是"进账单时默认勾了哪些"，玩家可增删。
一般写清 `ingredients` 就够了；后两个按需再加。

### 配方到底"挂"在哪个工作台？三种机制

| 机制 | 写在哪 | 什么时候用 |
|---|---|---|
| `recipeUsers` | **配方**里，点名工作台 | 本章这种"加工类"配方，最常用 |
| `<recipes>` | **工作台**的 ThingDef 里，点名配方 | 你自己写了工作台（如第 10 章），想集中列出它能做的配方 |
| `recipeMaker` | **物品**的 ThingDef 里 | 做武器/服装时，物品自己声明"怎么做"，游戏自动生成配方（见 03-xml-defs 的武器示例） |

> 前两个是**同一根线的两头**：配方写 `recipeUsers`、或工作台写 `<recipes>`，效果一样，**写一边即可**，游戏会合并。别两边重复写。`recipeMaker` 则是另一条省事的路——专为"可制作的物品"准备。

## 11.2 ResearchProjectDef：科技树上一个节点

再建 `Defs/ResearchProjectDefs/PMM_Research.xml`，把上面引用的 `PMM_RockCrushing` 研究真正定义出来：

```xml
<?xml version="1.0" encoding="utf-8"?>
<Defs>
  <ResearchProjectDef>
    <defName>PMM_RockCrushing</defName>
    <label>rock crushing</label>
    <description>Learn to break down stone chunks and recover usable steel.</description>

    <baseCost>800</baseCost>                  <!-- 研究点数，越大越慢 -->
    <techLevel>Industrial</techLevel>         <!-- 科技等级 -->

    <!-- 前置研究：得先做完原版的 Machining -->
    <prerequisites>
      <li>Machining</li>
    </prerequisites>

    <!-- 在研究界面的位置（网格坐标，自己挪到不压别人的地方） -->
    <researchViewX>7</researchViewX>
    <researchViewY>2</researchViewY>
  </ResearchProjectDef>
</Defs>
```

**字段速查：**

| 字段 | 含义 |
|---|---|
| `baseCost` | 需要多少研究点。数值越大做得越慢，参考原版同级研究取个量级即可 |
| `techLevel` | 科技等级：`Neolithic` / `Medieval` / `Industrial` / `Spacer` / `Ultra`（注意是 `Ultra`，**不是** `Ultratech`） |
| `prerequisites` | **前置研究**列表，写别的研究的 `defName`。全做完，本研究才解锁 |
| `researchViewX` / `researchViewY` | 本节点在研究界面的**横/纵坐标**。只是摆位置，叠到别人就挪一挪 |
| `tab` | 归到哪个研究页签（默认 `Main`），可选 |

## 11.3 三者是怎么串起来的

把整条链对着 defName 看一遍，引用关系一目了然：

```
PMM_RockCrushing（研究）          ──定义于──▶  PMM_Research.xml
   ▲                                        prerequisites 里写了 Machining（原版研究）
   │ researchPrerequisite = PMM_RockCrushing
PMM_Recipe_CrushChunkToSteel（配方）──定义于──▶  PMM_Recipes.xml
   │ recipeUsers 里写了 TableMachining       products 里写了 Steel
   ▼                                        （想产第 9 章的物品，就换成它的 defName）
TableMachining（工作台，原版）  →  小人做账单  →  产出 Steel（物品）
```

**一句话**：研究做完 → 配方因 `researchPrerequisite` 解锁 → 配方因 `recipeUsers` 出现在工作台上 → 小人干满 `workAmount` → 按 `products` 产出物品。要把它接到你自己第 9、10 章的成果上，只需把 `products` 和 `recipeUsers` 里的 defName 换掉。

## 11.4 常见坑 & 速查表

1. **材料/产品的 defName 写错**：`ingredients`、`products` 里写的必须是**真实存在的 ThingDef 的 defName**（区分大小写）。写错 → 加载红字 "Could not resolve cross-reference"，或配方材料是空的。**先查原版再抄。**
2. **prerequisites 引用了不存在的研究**：前置研究的 defName 必须真实（原版如 `Machining`，或你 mod 里已定义的）。写错 → 红字、研究不显示。
3. **三个名字像到分不清**（最容易踩）：
   - 配方要研究 → `RecipeDef` 里写 **`researchPrerequisite`（单数）**；
   - 建筑要研究才能造 → 建筑 `ThingDef` 里写 **`researchPrerequisites`（复数）**；
   - 研究自己的前置 → `ResearchProjectDef` 里写 **`prerequisites`**。
4. **techLevel 写 `Ultratech`**：合法值是 **`Ultra`**（第 2 章就强调过的反面教材）。
5. **配方没出现在工作台**：检查 `recipeUsers` 写的是不是工作台的 **defName**（不是 label）；以及有 `researchPrerequisite` 时，**研究没做完配方是隐藏的**——先确认研究做完了。
6. **研究节点叠在一起**：`researchViewX/Y` 没调好会压住原版节点，进游戏看着挪。

**铁律重申（第 2 章那条）**：字段名、defName、枚举值一律**先查原版**再写，别凭记忆。

## 动手练

1. **改产出/材料**：把 `products` 里的 `Steel` 换成你第 9 章做的物品的 defName（或把 `count` 调大），把 `ingredients` 的 `count` 改成 `1`。纯 XML，重启或重载后进游戏看账单变化。
2. **加前置 / 换工作台**：给研究 `prerequisites` 再加一条 `<li>Electricity</li>`，或把 `recipeUsers` 改成你第 10 章搭的工作台的 defName，体会"前置没做完/挂错台子，配方就消失"。

## 本章小结

- **RecipeDef** = 一张配方：材料（`ingredients`）、产出（`products`）、工作量（`workAmount`）、技能（`workSkill`/`skillRequirements`）、特效（`effectWorking`）。
- 配方靠 **`recipeUsers`**（或工作台的 `<recipes>`，二选一）挂到工作台；做武器/服装可用物品自带的 **`recipeMaker`** 省事。
- **ResearchProjectDef** = 科技树节点：`baseCost`/`techLevel`/`prerequisites`，位置用 `researchViewX/Y`。
- 三者靠 defName 串成"研究 → 解锁配方 → 工作台 → 产出物品"的链。
- 先查原版；当心 `researchPrerequisite`（单）/`researchPrerequisites`（复）/`prerequisites` 三个近名坑。
